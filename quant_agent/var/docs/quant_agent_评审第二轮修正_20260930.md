### 2. 快照不可变：承认旧机制失效，重建并验收（评审意见 2）

- 旧"0 修订"是假象：缓存更新为原地 open(w) 截断写，与硬链接共享 inode，冻结副本随源文件同步改变，比对永远无差异。
- 修正双层落地：
  1. **qdata 改为原子写**（tmp + os.replace）——正确更新姿势，源路径换新 inode，任何旧快照天然保留；
  2. **冻结副本改为独立拷贝 + 只读权限（0o444）+ 冻结清单自哈希**（frozen_manifest.json），巡检先做冻结侧完整性自检再比对。
- 验收：新增 S7 测试（tests/test_snapshot_immutability.py）——对源文件执行**原地覆盖、追加、删除重建、路径替换**四种操作，冻结哈希不变；篡改冻结侧能被清单检出。通过。

## 二、现金执行层的限定说明（评审意见 3 逐条回答）

| 问题 | 事实 | 证据 |
|---|---|---|
| 买入是否预留手续费 | 是：可买金额 = 现金÷(1+买费)，费用同步扣除，逐日现金≥0 | E6-1 |
| 卖单未成交是否误释放资金 | 否：卖出在成交时才入账；停牌顺延当日资金不跳升 | E6-2 |
| 截断买入后卖出按实际持仓 | 是：仓位以独立批次记实际股数，出场只按实际持仓生成 | E6-3 |
| 引擎退出规则是否依赖虚拟持仓 | 否：出场日程在信号日由特征计算确定（Keltner/到时），与是否成交无关；被跳过的意图不产生仓位与卖出 | 代码核验+E6-3 |
| 涨跌停/停牌/数量规则 | 引擎对意图单已做涨停禁买、跌停顺延；executor 复核停牌顺延与整手；**开盘价滑点与部分成交未建模** | E5/E6 |

补充澄清：**"部分成交未建模"与"整手为最小单位"是两个问题**——整手订单在真实市场仍可能部分成交，当前属于现金约束下的简化成交模拟，不证明真实执行能力。敞口上限语义：**下单时约束，非每日强制再平衡**；价格漂移可使市值敞口越限（仅当 cap<1 时可能发生，cap=1 时现金账户无负债、物理上≤100%），越限天数由 `exposure_breach_days` 如实记录。

## 四、口径敏感性归因：不承诺可加份额（评审意见 5）
